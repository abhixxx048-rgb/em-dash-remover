# Browser Extension (Clean-on-Paste / Right-Click)

> A companion Chrome/Edge (MV3) extension that runs the same grammar-aware cleaning engine inside any web page - clean selected text from the right-click menu, clean-on-paste into any field, and live-clean the output of ChatGPT/Claude/Gemini - so users never have to leave their writing surface to de-AI their text. Tier: 3. Difficulty: Med. Runs: client-side (100%, no network; reuses the existing in-browser `clean()` engine).

## 1. What it does

The extension ports the site's existing pure cleaning function (`src/lib/cleaner.ts` - `clean(input, opts): CleanResult`) into a Manifest V3 content script so the same em-dash/quote/invisible-char/whitespace cleanup that powers the website is available *in place*, on whatever page the user is writing on. Three modes share that one engine: (a) **right-click "Clean selection"** replaces selected text in any input, `textarea`, or `contenteditable` with its cleaned version; (b) **clean-on-paste** intercepts the `paste` event and inserts cleaned text instead of raw clipboard content; and (c) an opt-in **live-clean mode** for AI chat surfaces (ChatGPT, Claude, Gemini, Perplexity) that watches the answer DOM with a `MutationObserver` and normalizes em dashes/invisibles as the model streams. Everything runs locally in the browser; the extension makes zero network requests and requests no host data beyond the tab the user explicitly acts on.

## 4. Features - core (MVP)

1. **Shared cleaning engine (zero divergence)** - bundle the existing `clean(input, opts)` from `src/lib/cleaner.ts` directly into the content script. The extension and the website apply byte-identical rules; fixing a rule once fixes it everywhere. No new cleaning logic is written.
2. **Right-click "Clean selection"** - a `chrome.contextMenus` item shown only on the `selection` context. On click, the service worker messages the content script, which reads the live selection, runs `clean()`, and replaces it in place. Works in `<input>`/`<textarea>` (via `setRangeText`) and `contenteditable` (via an `insertText` `beforeinput` path).
3. **Undo-safe, framework-safe replacement** - for plain fields, use `el.setRangeText(cleaned, start, end, 'end')` then dispatch an `input` event, which **preserves the browser's native undo history**. For React/ProseMirror/Lexical editors (ChatGPT, etc.), drive the change through `document.execCommand('insertText', …)` / a synthetic `beforeinput` with `inputType:'insertText'` so the framework's own transaction system records it - direct `innerHTML` writes are explicitly avoided because the editor's next render overwrites them.
4. **Clean-on-paste (toggleable)** - a content-script `paste` listener that reads `clipboardData.getData('text/plain')` (and `text/html` where the Word/Docs cleaner logic applies), `preventDefault()`s, cleans, and inserts the result. Off by default per-site; the user enables it where they want it to avoid surprising paste behavior.
5. **Popup control panel** - the toolbar popup exposes the same option toggles as the website (`dashStyle`, en-dashes, smart quotes, ellipsis, invisibles, whitespace, markdown), persisted in `chrome.storage.sync`, plus a global on/off and a per-site enable list.
6. **Color-coded toolbar badge** - green = active on this site, grey = off, matching the proven undash pattern so users can see state at a glance.
7. **Live-clean mode for AI chat (opt-in)** - on an allow-list of chat hosts (chatgpt.com, claude.ai, gemini.google.com, perplexity.ai), a `MutationObserver` (`childList` + `characterData` + `subtree`) watches the message container and cleans new/streamed answer text. Debounced and applied only to assistant messages so it doesn't fight the user's own typing.
8. **Per-message "Clean this reply" button** - a lighter alternative to live mode: inject a small button into each assistant message that cleans just that message's rendered text on demand.
9. **Keyboard shortcut** - a `chrome.commands` binding (e.g. Alt+Shift+C) to clean the current selection without the mouse.
10. **Minimal permissions** - `contextMenus`, `storage`, `scripting`, and **`activeTab`** for on-demand actions, with host permissions for the chat allow-list requested **optionally** (`optional_host_permissions`) and granted by the user only when they turn live mode on. No broad "read and change all your data on all websites" by default.
11. **No network, no telemetry** - the content script and worker make zero `fetch`/XHR calls; a published privacy policy and the open-source content script back the claim (undash and DashAway both lean on exactly this).

## 5. Features - engagement & helpfulness (what makes users love it & stay)

This is the section that turns a me-too em-dash stripper into the one users keep installed. Each item says *why* it helps.

1. **One-keystroke clean anywhere (no copy-out round-trip)** - the entire value is removing the "select → copy → open website → paste → clean → copy → paste back" loop down to a single right-click or shortcut. *Why:* this friction-removal is the whole reason the category exists; it's what earns the install and the daily reuse instead of a one-time website visit.
2. **Live before/after toast on every clean** - after a clean, a small non-blocking toast shows "Cleaned: 4 em dashes → commas, 2 invisible chars removed, 6 curly quotes straightened" with an **Undo** link. *Why:* proves the tool actually did something (incumbents silently mutate text, which feels untrustworthy), and the inline undo removes all fear of it mangling content.
3. **Native, undo-safe edits** - because edits go through `setRangeText`/`insertText` rather than clobbering the value, the user's own Ctrl+Z still works exactly as expected. *Why:* the #1 way these extensions lose trust is wiping undo history or breaking the editor; getting this right is invisible when it works and infuriating when it doesn't.
4. **"Why this is a tell" micro-education on hover** - the toast and popup link tells to short explanations ("AI over-uses em dashes for dramatic pauses; here's the human alternative"), pulling from the site's existing blog content. *Why:* it differentiates on *quality and learning* (the brand's whole position) rather than "beat the detector," and it pulls users back to the website's articles.
5. **Per-message "Clean this reply" button in ChatGPT/Claude/Gemini** - a quiet button on each AI answer. *Why:* meets users at the exact moment of need (reading AI output) without the heavier commitment of always-on live mode; it's the single most "it gets me" touch for the core audience.
6. **Color-coded badge + per-site memory** - green/grey badge, and the extension remembers which sites you enabled clean-on-paste or live mode on. *Why:* gives constant ambient feedback about state and avoids the annoyance of surprising paste behavior on sites where you didn't want it - control breeds trust, trust breeds retention.
7. **Highlight-only "audit this page" mode** - a read-only toggle that outlines every em dash, en dash, and invisible/zero-width char on the current page with a count badge (no mutation). *Why:* serves the editor/QA audience and the validated "Em-dash Page Analyzer / M-Dash Detector" niche, and lets cautious users *see* before they let the tool change anything.
8. **Options presets ("Smart" / "Plain" / "Publish")** - one-click profiles in the popup (Smart = grammar-aware default; Plain = strip everything to bare prose; Publish = keep curly quotes and proper dashes for polished output). *Why:* different surfaces want different results (a tweet vs. a CMS), and presets beat hunting through seven checkboxes every time.
9. **Live counter in the popup** - shows a running "X em dashes, Y invisibles, Z smart quotes cleaned today/this session." *Why:* a lightweight gamified sense of payoff that makes the tool feel valuable and keeps it pinned.
10. **Keyboard-first workflow** - a rebindable shortcut to clean the selection, plus the right-click. *Why:* power users live on the keyboard; a shortcut converts an occasional-use extension into muscle memory.
11. **Sync across devices via `chrome.storage.sync`** - settings and per-site preferences follow the user to their other machines. *Why:* a logged-in Chrome user gets a consistent experience everywhere, lowering re-setup friction and increasing stickiness.
12. **Empty/first-run onboarding card** - first install opens a one-screen guide: "Select text anywhere → right-click → Clean selection," with a live demo box to try it immediately. *Why:* extensions die from "installed but never figured out how to use it"; a 10-second success moment drives activation and review rates.
13. **Dark-mode-aware UI** - popup and injected toasts/buttons respect the page's and OS color scheme. *Why:* injected UI that flashes white on a dark ChatGPT page feels broken; matching the surface keeps it feeling native.
14. **Accessible, non-color-only feedback** - toasts and badges pair color with an icon and text label; the audit highlights use an outline + icon, not color alone. *Why:* WCAG compliance and usability for color-blind users, and it makes the feedback legible against arbitrary page backgrounds.
15. **"Open in full cleaner" escape hatch** - the popup has a link that opens the website with the current selection prefilled (via the extension copying it across). *Why:* for big or tricky text, it hands users to the richer website UI (diff viewer, AI-tell report) - turning the extension into a top-of-funnel that *feeds the site* rather than cannibalizing it.
16. **Quiet, debounced live mode** - live-clean only touches finished assistant messages, debounced, never the user's in-progress typing. *Why:* the fastest way to get uninstalled is an extension that fights the cursor; restraint here is a feature.

## 6. UX / UI notes

- **Three entry points, one engine:** right-click context-menu item (always available on a selection), the toolbar popup (settings + on/off + counters + presets), and opt-in injected UI (per-message clean buttons, live-mode toggle) on allow-listed chat sites.
- **Input/output model:** the page *is* the canvas. There is no paste-box; the "input" is the user's live selection, paste event, or an AI message, and the "output" replaces it in place. The only first-class chrome the extension owns is the popup and transient toasts.
- **States:**
  - *Idle:* grey badge, context menu present but inert until something is selected.
  - *Active on site:* green badge; clean-on-paste/live mode (if enabled here) running.
  - *Processing:* effectively instant for selections; for live streaming, a subtle "cleaning…" pulse only if a batch is large.
  - *Result:* a 2-3s toast summarizing changes with an Undo link; if nothing needed cleaning, a "Already clean ✓" toast so the action never feels like a no-op.
  - *Permission-needed:* turning on live mode prompts the optional host-permission grant inline with a one-line rationale.
- **Microcopy tone:** plain, calm, quality-first - "Cleaned 4 em dashes," "Already clean," "Keep your human voice." Never "make it undetectable / beat the detector."
- **Mobile behavior:** desktop Chrome/Edge only (extensions don't run on mobile Chrome); the popup gracefully states this and points mobile users to the website, which is the mobile surface.
- **Accessibility:** popup is keyboard-navigable with visible focus rings and ARIA labels; toasts are `role="status"` (polite live region) so screen readers announce results; all feedback pairs color with text/icon (no color-only signals); respects `prefers-reduced-motion` for the toast/pulse animations and `prefers-color-scheme` for theming. Target WCAG 2.1 AA on the popup and injected controls.

## 7. Technical implementation (client-side)

- **Manifest V3 structure:** a service worker (`background.js`) that registers the context menu and `commands`, routes messages, and owns no DOM; a content script injected on demand (via `chrome.scripting.executeScript` under `activeTab`) for right-click/paste, plus a declaratively-injected content script on the chat allow-list for live mode; a popup (`popup.html/js`) for settings.
- **Engine reuse (zero new cleaning logic):** import the existing pure `clean(input: string, opts: CleanOptions): CleanResult` from `src/lib/cleaner.ts`. It already returns the cleaned string **and** a per-rule change inventory (`CleanResult`), which the toast/counter consume directly. Bundle it (esbuild/Vite) into the content script - it's pure string logic, no DOM/network deps, so it ports unchanged.
- **Selection replacement algorithms:**
  - *Plain fields (`input`/`textarea`):* read `el.value.slice(el.selectionStart, el.selectionEnd)`, run `clean()`, then `el.setRangeText(cleaned, el.selectionStart, el.selectionEnd, 'end')` and dispatch a bubbling `InputEvent('input')`. **`setRangeText` preserves native undo** - the key reason to prefer it over `el.value = …`.
  - *`contenteditable` / framework editors (ProseMirror/Lexical/Slate):* the visible DOM is a *projection* of an internal immutable state tree, so writing `innerHTML` is overwritten on the next render. Replace the selection range, then drive the change through `document.execCommand('insertText', false, cleaned)` or a synthetic `beforeinput` with `inputType:'insertText'` (and `composed:true` to cross shadow boundaries) so the framework's transaction system commits it. `execCommand('insertText')` is deprecated but remains the only reliable cross-framework path; gate it behind a capability check and fall back to a range replacement + `input` dispatch.
- **Clean-on-paste:** `addEventListener('paste', …, {capture:true})`, read `clipboardData`, `preventDefault()`, clean, and insert via the same field-type-aware path above. Reuse the Word/Docs `text/html` cleanup only on surfaces where rich paste matters.
- **Live mode (MutationObserver):** observe the chat's message list with `{childList:true, subtree:true, characterData:true}`; on mutations, find newly-settled **assistant** message nodes (selector per host, behind a small adapter map), debounce ~300ms after streaming stops (detect by mutation quiescence), and clean their text nodes. Guard against feedback loops by marking nodes processed (`data-` flag) and ignoring self-induced mutations. DashAway proves the real-time, content-added-while-you-use-it pattern works.
- **Unicode/regex:** identical to the website - em dash `U+2014`, en dash `U+2013`, curly quotes `U+2018/2019/201C/201D`, ellipsis `U+2026`, NBSP `U+00A0`, narrow NBSP `U+202F`, zero-width `U+200B–200D`, BOM `U+FEFF`, word-joiner `U+2060`, variation selectors `U+FE00–FE0F`. All live in `cleaner.ts` already; nothing re-implemented.
- **Performance:** selection cleans are sub-millisecond on normal text. Live mode is the only perf risk - mitigated by debouncing, per-node processed flags, observing the narrowest message container (not `document.body`), and skipping nodes whose text contains no target characters (cheap pre-filter) before invoking `clean()`.
- **Edge cases & failure modes:** password fields and `input[type=number/email]` (skip non-text inputs); cross-origin iframes (content script must be injected per-frame or the action no-ops gracefully); shadow-DOM editors (use `composed` events; some closed shadow roots are simply unreachable - degrade silently); editors that reject synthetic events (fall back to range replacement); very large selections (chunk or warn). Always no-op safely rather than corrupting text.
- **Server/LLM:** **none.** There is no rewrite/LLM in this tool - it's the deterministic engine only - so the privacy story is airtight: zero hosts beyond the chat allow-list (and those are *optional*, user-granted), zero network calls, open content script, published privacy policy. This mirrors and beats undash/DashAway's "runs only in your browser" claim because ours is verifiable against an open-source website engine.

## 8. Competitors & how we differentiate

- **undash** (Chrome Web Store, Product Hunt) - closest analog: clean-on-paste, right-click clean selection, color-coded toggle badge, free, local, tested on LinkedIn/Gmail/Twitter/Facebook. *Weakness:* em dash **only**, blind replace (typically em dash → space), no grammar awareness, no quotes/ellipsis/invisible-char/markdown cleanup, no education, no audit mode, no website behind it.
- **DashAway** (github.com/ronxldwilson/DashAway) - live-cleans ChatGPT/Claude/Gemini/Perplexity/Bard output in real time via DOM monitoring; local, no data sent. *Weakness:* GitHub-only (not on the Web Store → high install friction), em dash only, removes *all* em dashes indiscriminately, no settings/presets, no undo feedback.
- **Em-Dash Replacer** (Chrome Web Store, em-dash-replacer.com) - removes em dash, en dash, and hyphen for "more natural" text. *Weakness:* explicitly bypass-framed, blunt (strips hyphens too, which corrupts legitimate text), single-purpose.
- **Em Dash Optimizer** (Web Store, vercel app) - one-click "messy em dashes → clean punctuation." *Weakness:* manual one-click only, no in-field/paste/live modes, single rule.
- **Em-dash Page Analyzer / M-Dash Detector** (Web Store) - read-only highlight/count of em dashes on a page. *Weakness:* detect-only, can't fix anything, single character.
- **Our wedge:** (1) **Grammar-aware, context-correct** replacement instead of blind global swap. (2) **The whole consolidated cleanup** - dashes + en dashes + curly quotes + ellipsis + invisible/zero-width chars + whitespace + markdown - in one engine, where every rival does one character. (3) **Quality, not bypass** positioning ("keep your human voice"), backed by an educational "why this is a tell" layer. (4) **Provable privacy** tied to an open website engine and minimal/optional permissions. (5) **Suite synergy** - the extension is top-of-funnel for the full website (diff viewer, AI-tell report, readability), with an "open in full cleaner" handoff none of the standalone extensions can offer. (6) **Edge + Chrome** from one MV3 build, into an under-served store.

## 10. Build effort & priority

- **Effort:** Medium. The cleaning engine is **already done and reused as-is** - no new core logic. The work is the MV3 shell (manifest, service worker, popup, storage), the three replacement paths (the `setRangeText` + `execCommand('insertText')` framework-safe insertion is the trickiest part and needs per-editor testing on ChatGPT/Claude/Gemini), the `MutationObserver` live mode with debouncing/loop-guards, the toast/counter UI, and Web Store + Edge submission (privacy policy, screenshots, minimal-permission justification to pass review faster).
- **Dependencies on existing code:** hard dependency on `src/lib/cleaner.ts` (`clean`, `CleanOptions`, `CleanResult`, `DEFAULT_OPTIONS`) - these port unchanged. Optional reuse of the Word/Docs `text/html` cleanup for rich clean-on-paste, and the AI-tell/blog content for the education layer. Build tooling (Vite/esbuild) to bundle the shared engine for the content script.
- **Recommended sequencing:** this is correctly placed as a **Tier-3 strategic bet** - ship it *after* the website tool hub (Tier 1 + the Tier 2 AI-Tell Report) has organic traction, so the extension's "open in full cleaner" handoff lands on a rich destination and the install page can cross-link a real suite. Within the build: (1) MVP = right-click "Clean selection" + popup settings + badge (covers the head keyword and the undash use case with a few days of work on a stable engine); (2) add clean-on-paste; (3) add per-message "Clean this reply" buttons on the chat allow-list; (4) add full live mode last (highest QA cost, highest uninstall risk if it misbehaves). Submit to Chrome first, then Edge (same build), keeping host permissions optional to speed review and avoid the scary all-sites warning.
